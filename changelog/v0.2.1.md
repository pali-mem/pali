# v0.2.1 - 2026-10-25

## Fixed

- Ranking: routed (temporal / person / multi-hop) queries no longer saturate the head of the ranking to `1.0`.
  The route boost was multiplied into a `[0,1]` score and clamped, which tied the top candidates and made
  their order arbitrary. A `total == 0 -> 1` fallback also promoted the lowest-relevance candidate to rank 1.
  Both replaced by a bounded additive blend (`0.85 * total + 0.15 * route`).
- Ranking: final candidate sort now uses the ID-tiebreaking comparator so equal scores are deterministic.
- Parser: prepared-fact dedupe keys on normalized content plus kind. Keying on the inferred
  entity/relation/value triple let byte-identical facts through when only the heuristic `Value` differed.
- Parser: month/time tag regex no longer matches ordinary words (`married`, `maybe`, `mayor`, `junior`,
  `decide`, `novel`, ...). `may` now requires an adjacent day or year; bare years are limited to 19xx/20xx.
  Same fix applied to the answer-metadata month pattern.
- Parser: single-sentence utterances are no longer emitted twice (whole-utterance form plus an identical
  per-sentence form). Multi-sentence utterances keep the whole form, which carries cross-sentence context
  that multi-hop questions depend on.
- Parser: pronoun subjects (`she`, `it`, ...) are never treated as resolved entities, so they no longer
  become graph nodes.
- Parser: content length alone no longer bypasses the informativeness filter; long questions and chatter
  are rejected like short ones.
- Heuristic importance scorer: replaced the TF-IDF-like term, which had no document frequency and scored
  `"ok"` at 1.00 and a dense biographical fact at 0.25. Base score is now log-scaled distinct informative
  tokens; preference/obligation words and numeric anchors add a small boost. `BatchScore` honours context
  cancellation.
- Repository: `Touch` no longer rewrites `updated_at` on read. That created a feedback loop where retrieving
  a memory made it rank higher on the next query via the BM25 tiebreak and recency fallback.
- Retrieval: lexical candidates now carry the real FTS5 BM25 score, normalized per query so the best hit is 1.0,
  via a new optional `MemoryScoredSearchRepository` extension implemented by the SQLite repository. Rank position
  is only used as a fallback for backends that cannot expose a score. Before, every query variant's top hit got a
  near-1.0 lexical score regardless of match strength.
- Retrieval: a bare `and` joining noun phrases ("Mel and her husband", "black and white") no longer classifies a
  query as multi-hop. The text after the conjunction must read as its own clause (wh-word, auxiliary, or verb).
  Measured over all 1977 LoCoMo questions, the old flag fired on 13% of true multi-hop and 13% of single-hop
  questions, so it carried no category signal while disabling both rerank stages.
- `goal` relation normalization was unreachable because the `plan` case matched `goal` first.

- `pali init` failed outside a source checkout (`open pali.yaml.example: no such file or directory`) because release archives ship only the binary.
  It now falls back to a copy of `pali.yaml.example` embedded at build time; a local file still takes precedence.

## Removed

- Dead config keys that were validated and wired but never read: `retrieval.temporal_resolver_enabled`,
  `retrieval.open_domain_alternative_resolver_enabled`, `parser.dedupe_threshold`, `parser.update_threshold`.
  Old YAML containing them still loads (unmarshal is non-strict).
- Dead package `internal/core/retrieval` (no importers) and unused `scoring.Weights`/`Score`/`Relevance`.
- Dead scaffolding: `parserPendingWrite.dropped`/`replacedBy`, `timeLayout.hasClock`, duplicated
  `StoreRawTurn` branches, local `maxInt`/`maxFloat64` helpers.

## Benchmark (lexical, heuristic parser, LoCoMo paperlite 200q, top_k=10, extractive, seed 1337)

| metric | before | after |
|---|---|---|
| Recall@5 | 0.257 | 0.255 |
| Recall@10 | 0.444 | 0.445 |
| nDCG@10 | 0.264 | 0.269 |
| MRR | 0.238 | 0.245 |
| F1 (extractive) | 7.71 | 7.66 |

Per query: hit@10 gained 1, lost 2; best rank among shared hits improved on 22 queries, worsened on 12.
Recall is unchanged, ordering inside the top 10 is better (the saturation fix), F1 is flat within noise at n=200.
Multi-hop extractive F1 moved 2.21 -> 1.26 on 39 questions with identical hit sets; that is one answer-selection
change, not a retrieval regression. The retrieval ceiling is recall of scattered evidence, which none of these
fixes address; they remove incorrect behaviour rather than add capability.

An earlier variant that dropped the whole-utterance observation entirely cost 4 multi-hop hits and was reverted.

Round 2 (retrieval review items 1-4), same lane, each measured against the previous step:

Grounded-context siblings are frequently the gold raw turn behind a top-ranked fact, so bounding them costs rank;
the review's dilution hypothesis does not hold on this benchmark. Caveat for the BM25 and dense-weight rows: this
lane runs `embedding_provider=lexical`, so the "dense" route is not a real embedding; rerun on the Ollama lane before
drawing conclusions about dense/lexical balance.
